# DIM9000 — Заявки

Неофіційний кабінет мешканця для ПК і телефона. Plain HTML/JavaScript,
інсталяція як PWA, хостинг фронтенду й бекенду в Base44. Є також локальна
версія на Python 3.10+ без сторонніх залежностей.

Підтримує список і пошук заявок, повні описи та відповіді, фото, діалоги,
історію статусів і термінів, пояснення УК зі сповіщень, оцінки,
створення заявок та повідомлень, текстове зведення й друк у PDF.
Видалення заявок відсутнє. Запис залежить від прав DIM9000; наприклад,
сервер дозволяє оцінку лише для статусу completed, хоча форма відкрита
для всіх статусів. Помилки сервера показуються користувачу.

## Хостинг у Base44

Потрібні Node.js 22+, Base44 акаунт і OAuth-конфігурація DIM9000.
Репозиторій не містить ключів, контактів, токенів або приватних заявок.

```sh
npm ci --ignore-scripts
npx base44 login
npx base44 link --create --name dim9000-zayavki
```

У Secrets створеного застосунку додайте:

| Секрет | Значення |
| --- | --- |
| OWNER_EMAIL | Email власника Base44: лише цей користувач може викликати API |
| DIM9000_CLIENT_ID | OAuth client ID мобільного застосунку |
| DIM9000_CLIENT_SECRET | OAuth client secret мобільного застосунку |
| SESSION_ENCRYPTION_KEY | 32 випадкові байти у hex, 64 символи |

Ключ шифрування можна згенерувати через `openssl rand -hex 32` і зберегти
безпосередньо в Secrets. Не змінюйте його без потреби: наявні сесії
втратять можливість розшифрування. Секрети також можна передати командою
`npx base44 secrets set --env-file .local/base44.env`. Цей файл має
залишатися приватним і не входить до Git.

```sh
npx base44 deploy --build -y
```

Використовуйте HTTPS URL, який поверне Base44. Власний домен можна
підключити пізніше в налаштуваннях Base44; для роботи він не потрібний.
Сторінка входу публічна, а backend перевіряє OWNER_EMAIL перед доступом
до даних. Це не потребує платної опції Private Apps у Base44.
Після входу в Base44 увійдіть у DIM9000 через SMS. Кожен браузер має
власну сесію. Вихід із DIM9000 видаляє її; вихід із Base44 виконується
через налаштування акаунта Base44.

Android/Chrome: меню браузера → Встановити застосунок / На головний екран.
iPhone/Safari: Поділитися → На початковий екран.
Інтернет потрібний для актуальних даних і змін. PWA не зберігає приватні
заявки офлайн і не повторює записи автоматично після втрати зв’язку.

## GitHub Actions

Workflow `Check and publish` перевіряє Python і JavaScript, публічний
вміст, залежності та PWA build. Pull requests не отримують секретів.
Деплой запускається тільки з main після успішних перевірок.

Налаштуйте в GitHub → Settings → Secrets and variables → Actions:

- Variable BASE44_APP_ID: ID створеного застосунку.
- Secret BASE44_DEPLOY_TOKEN: окремий Base44 personal access token,
  обмежений цим застосунком, із дозволом редагування/deploy.

Без BASE44_APP_ID деплой пропускається. Після налаштування запустіть
workflow вручну або зробіть push у main. Backend-секрети налаштовуються
в Base44 окремо й ніколи не передаються у frontend build.
CLI версію зафіксовано; CI використовує його локальний формат auth.json
для Bearer personal access token і видаляє файл після завершення job.
Перевірте перший live run після додавання токена; при відмові прав deploy
має завершитися помилкою, а не публікувати частково перевірений результат.

## Локальний запуск

```sh
cd dim9000-zayavki
python3 server.py
```

Відкрити http://127.0.0.1:9000. Інший порт: `--port 9001`.
Перед SMS-входом задайте DIM9000_CLIENT_ID і DIM9000_CLIENT_SECRET
у середовищі або збережіть їх як CLIENT_ID і CLIENT_SECRET у приватному
.local/oauth.json. Локальні токени лежать у .local/tokens.json з правами
0600. Ця версія слухає лише localhost і не призначена для публічного доступу.

## Перевірки

```sh
python3 -m unittest discover -s tests -v
npm test
node --check static/app.js
BASE44_APP_ID=ci-build npm run build
python3 scripts/check-public.py
```

Тести використовують синтетичні дані. Реальні тестові заявки, повідомлення
й оцінки не створюються. При таймауті запису спочатку оновіть дані,
щоб не створити дубль. Посилання на вкладення в експорті можуть спливати.
API досліджено в [docs/API.md](docs/API.md), архітектуру хостингу описано
в [docs/HOSTING.md](docs/HOSTING.md).
